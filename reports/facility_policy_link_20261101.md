# 공간분석 → 시설 추가 시나리오 → 정책 연결

## 기존 기능 확인

`src/gap/siting.py`는 기존 공급에 가상 시설을 추가하고 2SFCA를 다시 계산한다.
전체 주민을 공급 경쟁 분모로 사용하며, 행정동별 집계구 인구가중 중심점이 수요점이자 후보점이다.
1·3·5km 후보 비교, 복수 시설 동시 추가, 탐욕 방식 후보 순서 비교를 지원한다.
전후 점수는 시설 추가 전의 접근성 min/max로 고정하고 상한을 1로 자른다.

기존 화면은 격차 점수·순위·외국인 가중 평균 위주이며 원시 접근성과 지역별 공급 변화는 표시하지 않았다.
기본 규모는 의사 3명이나 공급 기준선 자체는 병의원·약국의 혼합 단위다.
`reports/m7_siting.md`의 과거 결과는 기록으로 보존한다. 기존 후보 순서는 필요 시설 수나 최적 부지를 산정하지 않는다.

## 공급 정의와 선정 기준

- 병의원: `src/ingest/datagokr.py`의 기존 총의사수 정의를 유지한다. 총의사수 0은 1로 대체한 공급 프록시이며 총량은 1,354다. 치과·한방 등을 포함하고 진료 기능·운영시간은 구별하지 않는다.
- 약국: 1개소당 공급량 1, 237개소다. 약사 수가 아니다.
- 혼합 기준선: 1,354 + 237 = 1,591. 서로 다른 단위가 합산된 기존 분석이며 해석에 한계가 있다.
- 별도 비교 화면의 원본 총의사수 1,323명(0 대체 없음)과 구별한다. 이번 전후 비교에서 그 값으로 공급 기준선을 바꾸지 않는다.
- 기본 분석(3km·외국인 비율·수요/접근성 결핍 각 0.5)의 **1위 구룡포읍**을 선정한다. 외국인 주민 1,147명, 전체 주민 7,617명, 격차 점수 0.8826822272다. 가중치는 비교용 기본값이다.

## 실제 계산 결과

두 시나리오는 동일한 기존 공급에 각각 따로 추가한다. 병의원과 약국을 동시에 추가한 결과가 아니다.

| 3km 시나리오 | 구룡포읍 혼합 접근성 전 → 후 | 변화율 | 해당 유형만의 접근성 전 → 후 | 격차 점수 전 → 후 |
|---|---|---|---|---|
| 병의원 1곳·의사 3명 가정 | 0.00183799 → 0.00223185 | +21.43% | 0.00144414 → 0.00183799 | 0.883 → 0.851 |
| 약국 1개소 가정 | 0.00183799 → 0.00196928 | +7.14% | 0.00039386 → 0.00052514 | 0.883 → 0.872 |

혼합 접근성의 단위는 혼합 공급/주민이며, 해당 유형 접근성은 각각 병의원 공급 프록시/주민, 약국 개소/주민이다.
3과 1이라는 가정 차이 및 공급 단위 차이로 증가량이 달라지므로 병의원 설치가 약국보다 효과적이라는 결론을 내리지 않는다.
의사 3명은 기존 입지 기능의 예시 규모이며 수요에서 추정한 규모가 아니다.

가상 시설의 3km 반경에 포함되는 대표 수요점은 구룡포읍 하나다.
추가 접근성은 병의원 `3/7617`, 약국 `1/7617`이다. 구룡포읍 외 28개 지역의 접근성과 점수는 변하지 않는다.
가장 가까운 다른 수요점은 호미곶면 약 7.98km, 다음은 동해면 약 8.80km라서 1·3·5km 모두 주변 수요점에 변화가 없다.
이는 행정동 경계까지의 거리나 실제 주변 주민의 이용 가능성을 뜻하지 않는다. 실제 파급효과가 없다는 결론도 아니다.

## 정책 카드·대시보드 연결

`src/policy/siting_evidence.py`가 기준선 점수를 저장된 분석과 대조한 후 2개 유형 × 3개 거리 × 29개 지역을 계산한다.
전체 지역 전후값과 변화 0도 CSV/JSON에 저장한다. 입력·구현 파일의 SHA-256을 함께 남긴다.
분리 접근성은 같은 기존 공급 정의로 해당 유형만 계산하며 별도의 격차 점수를 만들지 않는다.

대시보드는 선정 이유, 병의원/약국 및 거리 선택, 원시 접근성, 유형별 접근성, 격차 전후, 주변 지역 변화를 표시한다.
선정 지역의 연결 카드는 기본 3km 시나리오를 근거로 공간적 공급 보완 가능성을 우선 현장 검토하도록 안내한다.
통역·예약·동행은 주민·기관 면담에서 필요가 확인된 뒤 검토할 보완책으로 제한한다.
화면의 시나리오 선택은 기존 지도·정책 카드의 분석 기준을 변경하지 않는다.

원본 `policy_cards.parquet`는 변경하지 않는다. 원문 사실·해석·추가 확인·출처를 보존하고 우선 대응·보완 지원을 계산 근거로 연결한 별도 카드를 만든다.
이 연결 서술은 코드 템플릿으로 작성하며 LLM에 수치 해석을 다시 요청하지 않는다. 대시보드에는 동일한 연결 카드를 표시한다.
기존 작업 파일은 먼저 상태를 확인했고, 수정한 기존 파일의 작업 전 사본은 `/private/tmp/sw-siting-before-20261101/`에 보관했다.

## 재현·검증

```bash
.venv/bin/python -m src.policy.siting_evidence
.venv/bin/python -m src.viz.dashboard
.venv/bin/python -m pytest tests/test_siting_evidence.py tests/test_siting.py tests/test_dashboard.py -q
uv run --with playwright python scripts/check_facility_scenario_ui.py
```

기존 `--stage siting`도 연결 산출물을 생성한다. 별도 모듈 실행은 기존 입지 후보 파일을 재생성하지 않는다.
산출물은 `outputs/facility_scenario/`에 있다. 외부 데이터 수집이나 LLM API 호출은 사용하지 않는다.

- 계산·기존 입지·대시보드 테스트: 16개 통과.
- 브라우저: 6개 시나리오 모두 29행, 카드 계산 근거 연결, 기존 비교·입지 조작, 모바일 가로 넘침 검사 통과. JS 오류 없음.
- `scripts/ask_claude.sh`를 읽기 전용으로 호출했으나 `Not logged in · Please run /login`으로 실패했다. **Claude 리뷰는 미완료**이며 로그인 복구 후 같은 범위의 리뷰가 필요하다.

## 해석 범위

시설 추가에 따른 모형상 접근성 변화 시나리오다. **시설 몇 곳이 반드시 필요하다는 산정이나 설치 확정안이 아니다.**
실제 이동 경로, 진료과, 운영시간, 이용 경험, 인력·예산·부지를 확인해야 하며 언어·예약·동행 장벽의 유무는 이 계산으로 입증되지 않는다.
