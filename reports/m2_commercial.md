# M2 — 상가(상권)정보 ingest, 행안부/통계청 코드 불일치 발견 (`src/ingest/commercial.py`)

작성일: 2026-08-24
작성자: Claude Code
근거: `reports/m1_structure_proposal.md` 블로커 3 (상가정보 API 키 확보 후 ingest 코드 작성)

## 배경

`data.go.kr`에서 발급받은 `소상공인시장진흥공단_상가(상권)정보_API`로 포항시 상가업소 데이터를 가져오려 했다. README §5는 `adm_cd`를 통계청 행정동 코드(SGIS/KOSIS가 쓰는 체계, 경북=`37`)로 단일화하도록 정해 두었고, 이 프로젝트는 SGIS 경계로 이미 그 체계의 29개 행정동 코드를 확보한 상태였다(`reports/m2_admin_units.md`).

## 발견 — 두 코드 체계가 다르다

`storeListInDong` 오퍼레이션에 `divId=signguCd&key=37011`(포항 남구, SGIS 기준)로 질의하면 매번 `NODATA_ERROR`가 났다. 파라미터 이름 자체는 맞았다(필수 파라미터 누락 에러와는 다르게 뜸) — 원인을 좁히기 위해 시도(도) 단위로 전수 테스트했다:

| 시도 | ctprvnCd로 조회 | 결과 |
|---|---|---|
| 서울 | `11` | 정상 |
| 울산 | `26` | 정상 |
| 경기 | `31` | 정상 |
| 전남 | `36` | 정상 |
| 그 외 13개 시도(경북 `37` 포함) | | `NODATA_ERROR` |

처음엔 이 API의 데이터 커버리지 자체가 일부 시도만 있는 건가 의심했지만, **좌표 기반 반경검색(`storeListInRadius`)으로 포항 시청 인근을 조회하니 정상적으로 데이터가 나왔다.** 응답의 `ctprvnCd`를 보니 `"47"`(경상북도) — SGIS/KOSIS가 쓰는 `37`이 아니었다. 즉 이 API는 **행정안전부 법정동코드 체계**(경북=`47`, 경남=`48`, 전북=`45`... 시군구·행정동 코드도 전부 다른 값)를 쓰고, 앞서 통과했던 서울(`11`)·경기(`31`) 등은 두 체계에서 우연히 같은 2자리 코드를 쓰는 시도였을 뿐이다.

## 설계 — 코드 매칭 대신 좌표 조회로 우회

행안부 법정동코드 ↔ 통계청 코드 간 전국 크로스워크를 새로 만드는 대신(범위가 프로젝트 밖), **좌표 반경검색으로 코드 체계 자체를 우회**하기로 했다. 이미 SGIS로 확보한 29개 행정동 폴리곤이 있으니, 이후 행정동 배정은 (심평원 데이터처럼 이름 매칭이 아니라) point-in-polygon으로 처리하면 된다 — `admin_join.py`에 이미 있는 로직과 같은 패턴이다.

### 반경 상한 실측

`storeListInRadius`의 `radius` 파라미터를 이분탐색으로 실측한 결과 **10,000m가 상한**이다(11,000m부터 `INVALID_REQUEST_PARAMETER_ERROR`). `storeListInRectangle`(사각형 조회)은 그보다 훨씬 작은 면적에서도 막혀 반경검색보다 못 미더워 채택하지 않았다.

### 행정동별 반경을 다르게 계산

포항 도심(중앙동·죽도동·해도동 등)은 반경 1.5~2.5km 안에 다 들어가는데, 여기에 일괄 10km를 쓰면 서로 겹쳐서 같은 상가를 수십 번 중복 조회하게 된다. 그래서 SGIS 폴리곤의 **중심→최원거리 정점 실측값 × 1.15(margin)**, 상한 10km로 행정동마다 다른 반경을 계산했다(`commercial._dong_query_points()`). 결과:

- 29개 중 27개는 자기 영역이 10km 반경 안에 완전히 들어간다.
- **흥해읍**(실측 11.0km)·**죽장면**(실측 18.6km, 경북에서 가장 넓은 면)은 10km 상한에 걸려 완전한 커버리지가 아니다 — 특히 죽장면은 절반 정도만 커버된다. 두 지역 다 인구밀도가 낮은 농촌 지역이라 상가 자체가 적을 것으로 추정되지만, 확정된 한계로 남긴다.

### 의료기관 중복 방지

상가정보 데이터의 대분류(`indsLclsNm`)에 `보건의료`가 포함되어 있어(병의원·약국 등), 그대로 합치면 심평원 데이터(`datagokr.py`)와 같은 시설이 두 소스에서 중복 집계된다. capacity 산정 기준도 서로 달라(심평원=총의사수 proxy, 상가정보=규모 지표 없음) 맞추기 어려워, **`보건의료` 대분류를 원천 제외**했다.

## 산출물

`src/ingest/commercial.py`:
- `fetch_stores_in_radius(cx, cy, radius_m, num_of_rows)` — 좌표 반경 내 상가업소 페이지네이션 전체 조회(페이지당 최대 1,000행, 실측).
- `_dong_query_points()` — 29개 행정동별 (중심좌표, 반경) 계산.
- `fetch_pohang_stores()` — 29개 동 순회 조회 후 `fac_id` 기준 중복 제거.
- 출력 컬럼은 README §5 `facilities.parquet` 계약에 맞춤: `fac_id, fac_type(중분류), lon, lat, capacity(=1 고정)` + 참고용 `category_large/small`.

**실행 결과**: 28,985건(중복 제거 후, `보건의료` 제외). `fac_id` 전부 고유, `capacity` 전부 1, `보건의료` 0건 확인.

## 남은 한계

- 흥해읍·죽장면은 반경 상한 때문에 완전한 커버리지가 아니다(위 참고).
- 행정동 경계 근처(특히 흥해읍처럼 시 경계에 가까운 동)는 반경검색이 포항 밖 인접 시군 상가까지 끌어온다 — 의도된 동작이다: ingest 단계는 넓게 가져오고, 포항 경계 밖 레코드는 preprocess 단계(SGIS 폴리곤 point-in-polygon)에서 제외한다.

## 후속 — `facilities.parquet` 병합 완료 (2026-08-25)

`src/preprocess/admin_join.py`에 `load_commercial_facilities_with_admin_dong()`을 추가해 위에서 언급한 preprocess 단계를 구현했다. `load_admin_boundaries()`가 반환하는 29개 SGIS 행정동 폴리곤에 `gpd.sjoin(..., predicate="within")`으로 상가업소 좌표를 배정하고, `how="inner"`라 어떤 포항 행정동 폴리곤에도 속하지 않는 점(포항 밖으로 넘어간 반경검색 결과)은 조인 과정에서 자연히 빠진다.

**결과**: ingest 단계 28,985건 → 경계 밖 810건 제외 → **28,175건**이 행정동 배정을 받아 `facilities.parquet`에 들어갔다. 심평원 의료기관 908건과 합쳐 `facilities.parquet` 총 29,083건, `fac_id` 전부 고유, `adm_cd` 결측 0건 확인.

`fac_type` 어휘가 두 소스(심평원=종별코드명, 상가정보=업종중분류)로 완전히 달라 access 레이어가 "의료"만 걸러 쓰기 어려울 수 있어, `category_large` 컬럼을 추가했다 — 의료기관은 상가정보의 제외 대분류명("보건의료")을 그대로 재사용해 일관성을 맞췄다.

### ⚠ 금융 카테고리가 이 데이터셋에 없다

README가 목표로 하는 "의료·금융 2종 접근성 지수" 중 금융 쪽에 직접 영향을 주는 발견이다. 이 API의 업종대분류 목록(`largeUpjongList`)에는 `K1(금융·보험)`이 공식 분류로 존재하지만, **포항 전역(29개 동, 28,985건)을 조회한 결과에 금융·보험 대분류 레코드가 단 한 건도 없었다** — 도심 최다 밀집 지역(반경 10km, 1페이지 1,000건)만 따로 원본(필터링 전) 응답을 봐도 마찬가지였다. 실제로 나온 대분류는 소매·음식·숙박·부동산·시설관리·임대·교육·과학·기술·예술·스포츠·수리·개인·보건의료(제외 전)뿐이다.

소상공인시장진흥공단 데이터는 이름 그대로 **소상공인(자영업) 업소** 중심이라, 은행 지점처럼 대기업/금융기관이 운영하는 시설은 애초에 이 데이터셋의 수집 대상이 아닐 가능성이 크다 — 분류 체계에는 자리가 있지만 실제로 채워지지 않는 것으로 보인다(전국 단위로 검증하진 않았고, 포항 한정 관측이다).

**결론**: 이 API만으로는 M2의 "금융" 접근성 지수를 만들 수 없다. 은행연합회 점포 현황, 금융감독원 금융회사 정보 등 별도 소스를 찾아야 한다 — GM/AI융합 역할 담당자와 상의 필요.
