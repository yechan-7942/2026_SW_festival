# M0 데이터 감사 및 M1 파이프라인 구축

M0(데이터 해상도 검증 게이트)와 M1(수집·정제 파이프라인) 단계에서 나온 4개 문서(M0 감사 결과, M1 착수 구조 제안, 행정동 신·구 코드 매핑, 법정동/행정동 매핑)를 하나로 합쳤다. 원래 개별 문서였던 이유는 각 단계가 끝날 때마다 바로 기록했기 때문이고, 지금은 시간순으로 읽어도 자연스럽게 이어지는 내용이라 합본했다.

---

## 1부 — M0 데이터 해상도 검증 게이트: 감사 결과

작성일: 2026-08-14

README §2에 정의된 M0 체크리스트 4개 항목을 로컬 원본 파일(`Data/`) 실사 + KOSIS 원격 조회 + 웹서치로 실제 검증한 결과다. 추정이 아니라 직접 연 파일과 API 응답 기준으로 작성했다.

### 결론 요약 — 게이트 상태: **조건부 통과**

핵심 차단 조건이었던 "외국인주민현황이 행정동 단위로 확보되는가"는 **확보 가능(YES)**으로 확인됐다. 다만 그 데이터는 로컬 `Data/`에 이미 있는 게 아니라 KOSIS 원격 조회로 새로 가져와야 한다. 나머지 2개 항목(SGIS 코드 일치, 실태조사 응답형식)은 완전히 닫히지 않았지만, 둘 다 README가 이미 예견한 대안(코드 매핑 테이블, AI 1층 재정의)으로 흡수 가능한 리스크이지 설계 자체를 뒤엎는 문제는 아니다. 따라서 `src/access/` 설계 착수는 가능하되, 항목 2·3은 M1 진행 중 별도로 반드시 닫아야 한다.

### 항목 1. 외국인주민현황 최소 공표 단위 — 시군구 vs 읍면동

**확인 결과: 읍면동(행정동) 단위로 공표됨. 확보 가능.**

KOSIS에 「시군 및 읍면동별 내·외국인 인구현황」(orgId=216, tblId=`DT_216N_B000J2`, 출처: 경상북도주민등록인구통계)이라는 표가 존재하며, 포항시 산하 개별 행정동 단위로 항목이 분리되어 있다. 예를 들어 죽도동(코드 `15216A1100A37010B000J336`)의 외국인 인구는 다음과 같이 조회된다.

| 행정동 | 연도 | 외국인 인구(계) |
|---|---|---|
| 죽도동 | 2023 | 196명 |
| 죽도동 | 2024 | 209명 |
| 죽도동 | 2025 | 221명 |

항목 차원은 총인구/내국인/외국인 3종, 성별(계/남/여) 교차분류까지 지원한다.

**주의사항 (KOSIS 조사연혁 경고):** 이 표는 2000년(작성주기 연 1회→반기), 2011년(반기→분기, 연령별 통계 확대) 개편 이력이 있다. 개편 전후 구간을 하나의 연속 시계열로 이어붙여 해석하지 말 것.

**로컬 데이터와의 차이 — 중요:** `Data/경상북도_포항시_연도별인구현황_20260323.numbers`는 이 조건을 만족하지 못한다. 실제로 열어본 결과 이 파일은 **포항시 전체 단위 월별 시계열**(2006-12 ~ 2026-02, 200행)이며 행정동 구분이 전혀 없다. 즉 지금 로컬에 있는 파일은 M0가 요구하는 해상도가 아니고, 실제로 쓸 데이터는 `src/ingest/kosis.py`가 `DT_216N_B000J2`를 새로 pull하도록 설계해야 한다.

### 항목 2. 포항시 남구·북구 행정동 목록 ↔ SGIS 경계 코드 일치 여부

**확인 결과 (이 시점): 미해결. SGIS Open API 키가 없어 경계 파일과의 직접 대조는 이번 세션에서 수행하지 못함.** (→ 이후 M2에서 완전히 닫힘, 2부 참고)

다만 KOSIS 자체 행정동 코드 체계는 확보했다. 포항시 산하 행정동 목록(2026-08-14 기준 KOSIS 조회):

- **남구 (14개)**: 송도동, 청림동, 제철동, 효곡동, 대이동, 구룡포읍, 연일읍, 오천읍, 대송면, 동해면, 장기면, 호미곶면, 상대동, 해도동
- **북구 (22개)**: 중앙동, 학산동, 상대1동, 상대2동, 해도1동, 해도2동, 양학동, 죽도1동, 죽도2동, 용흥동, 우창동, 두호동, 장량동, 환여동, 흥해읍, 신광면, 청하면, 송라면, 기계면, 죽장면, 기북면, 죽도동

**중요한 발견:** 목록에 `죽도동`과 `죽도1동`/`죽도2동`이 동시에 존재하고, `해도동`(남구 소속)과 `해도1동`/`해도2동`(북구 소속)이 동시에 존재하며, `상대동`(남구 소속)과 `상대1동`/`상대2동`(북구 소속)도 동시에 존재한다. 과거 행정동 통폐합/분동 이력이 KOSIS 코드 체계에 신-구 코드로 남아있다는 뜻이다. `data/processed/adm_code_map.csv` 수작업 매핑이 필수 작업이 될 것으로 예상됐다(→ 실제로 필요했다, 3부 참고).

### 항목 3. 다문화가족실태조사 '지원 서비스 요구' 항목 — 응답 형식

**확인 결과: 미확정이지만, 객관식(사전 정의된 서비스 목록에 대한 체크리스트/척도)일 가능성이 높음.**

2021년 전국다문화가족실태조사 보도자료는 서비스 이용 경험을 "입국 전 교육 36.2%, 한국사회 적응교육 30.4%" 같은 형태로 보도한다. 사전 정의된 서비스 카테고리별 이용률(%)로 집계·보도된다는 것은 해당 문항이 자유서술형이 아니라 폐쇄형(체크리스트 또는 이용경험 유무 + 향후 필요도 척도) 구조라는 강한 정황 증거다.

**한계:** 원본 조사표(설문지) PDF는 여성가족부 홈페이지에서 JavaScript 트리거 다운로드 방식이라 브라우저 자동화 없이는 직접 열어보지 못했다. 100% 확정하려면 MDIS(mdis.kostat.go.kr)에서 실제 조사표/코드북 원본을 받아 '지원 서비스 요구' 문항 번호를 직접 확인해야 한다 — 이 보고서 작성 시점까지도 미해결이며, M4의 유일한 외부 블로커다.

**결론 — AI 1층 재정의 필요할 가능성 높음:** 위 정황이 맞다면 "NLP 토픽모델링" 서술은 성립하지 않는다. README가 제시한 대안 — **응답 패턴 기반 잠재클래스 분석(LCA) 또는 다변량 수요 프로파일링**으로 AI 1층을 재정의하는 방향을 권장한다.

### 항목 4. 상가정보·의료기관 데이터의 좌표계와 포항시 레코드 수

**확인 결과: 의료기관 데이터는 검증 완료. 상가정보는 이 시점에 아직 미확보.** (→ 이후 M2에서 확보, `reports/m2_commercial.md` 참고)

| 파일 | 전국 행 수 | 포항시 레코드 | 좌표 컬럼 | 좌표계(실측) |

| 1.병원정보서비스 | 79,562 | 671건 (북구 397, 남구 274) | `좌표(X)`, `좌표(Y)` | WGS84 십진 경위도 |

README가 우려했던 "도분초 문자열" 형식이 아니라 이미 십진(decimal degree) WGS84(EPSG:4326)였다 — `crs.py`에서는 4326→5179 재투영만 하면 된다. 또한 두 파일 모두 `읍면동` 컬럼에 행정동명이 원문 텍스트로 들어있어(예: 죽도동, 흥해읍) 이름 매칭으로 1차 조인이 가능해 보였다 — 다만 이 전제는 이후 3부에서 틀린 것으로 드러난다(법정동/행정동 불일치).

## 2부 — M1 착수를 위한 구조 제안

작성일: 2026-08-14

M0 감사 결과가 README 4절의 리포지토리 구조 안에서 **각 모듈이 어떤 입력을 받고 무엇을 먼저 처리해야 하는지**를 어떻게 바꾸는지 정리한 것. (제안 시점 문서라 이후 실제 구현에서 바뀐 부분은 3~4부에 실제 결과로 갱신되어 있다.)

- **`src/ingest/kosis.py` 우선순위 1순위.** `DT_216N_B000J2`를 pull해 포항시 행정동별 인구 시계열을 받는다. 로컬 `.numbers` 파일은 참고용으로만 남긴다.
- **`data/processed/adm_code_map.csv`가 예상보다 일찍 중요해짐.** SGIS 경계 파일과 대조하기 전에도 KOSIS 코드 체계 자체 안에서 신-구 행정동 중복 문제가 터질 수 있다 — ingest 직후 단계에 이 매핑 테이블을 세워야 한다.
- **`src/preprocess/admin_join.py` 조인 전략 두 단계.** 1차 이름 문자열 매칭, 2차 좌표(X,Y)→point-in-polygon 교차 검증. 두 결과가 갈리는 레코드가 신-구 동 매핑 문제가 실제로 터지는 지점이다.
- **`src/preprocess/crs.py`는 예상보다 간단해짐.** 심평원 데이터가 이미 EPSG:4326이라 4326→5179 재투영 한 줄이면 충분.
- **`src/nlp/demand.py`는 잠정적으로 토픽모델링 전제를 버림.** LCA/다변량 프로파일링을 1차 설계안으로 잡되, `demand_signals.parquet`의 인터페이스(README 계약)는 그대로 유지.
- **남은 블로커 (병렬 처리 가능):** SGIS Open API 키 발급, MDIS 원본 조사표 확보, 상가(상권)정보 다운로드. 세 가지는 서로 의존관계가 없다.

## 3부 — 행정동 신·구 코드 매핑 (`data/processed/adm_code_map.csv`)

작성일: 2026-08-22

M0 감사에서 KOSIS `DT_216N_B000J2`의 objL1(행정구역별) 코드에 죽도동/죽도1동·2동, 해도동/해도1동·2동, 상대동/상대1동·2동이 동시에 존재하는 걸 확인했지만, SGIS API 키가 없어 "어느 쪽이 현재 유효한 행정동인가"는 미해결로 남겨뒀었다(1부 항목 2). 이번 작업은 **SGIS 경계 파일 없이도** 확인 가능한 부분 — 행정안전부 행정구역 개편 이력 — 을 위키백과 교차 확인으로 먼저 닫은 결과다.

**방법:** `kosis_table_info(type=ITM, objId=15216A11)`로 포항시 산하 objL1 코드 전체(39건)를 조회 → 위키백과 "포항시의 행정 구역" 문서 + 개별 동 문서로 각 코드의 통합·분동 연혁을 교차 확인 → 두 결과가 일치하는지 대조. KOSIS에 남아있는 옛 코드(학산동, 상대1·2동, 해도1·2동, 죽도1·2동) 전부가 위키백과 통합 이력과 정확히 대응됨을 확인했다.

**핵심 발견:**

- **현재 유효한 포항시 읍면동은 29개다** (4읍 + 10면 + 15행정동). M0 문서가 "36개"로 집계했던 건 폐지된 옛 코드(학산동, 상대1·2동, 해도1·2동, 죽도1·2동 = 7개)를 함께 셌기 때문이다. `config/pipeline.yaml`의 대상 행정동 목록은 이 29개만 써야 한다 — 옛 코드까지 넣으면 인구·시설 데이터가 이중 집계된다.
- **구(區) 소속이 바뀐 사례가 있다.** KOSIS의 옛 코드 계층상 상대1동·상대2동·해도1동·해도2동은 **북구** 하위로 기록돼 있는데, 2009-01-01 통합 이후의 상대동·해도동은 **남구** 소속이다. 단순 문자열 매핑만으로는 이 구 소속 변경을 놓치기 쉽다.
- **죽도동은 반복 분동·통합 이력이 있다.** 1961→1966, 1970→2009 두 번 분동됐다가 재통합됐다.

**파일 형식:** `data/processed/adm_code_map.csv` — `adm_cd_kosis`, `adm_nm`, `gu`(현재 기준), `status`(current/deprecated), `current_adm_cd_kosis`/`current_adm_nm`, `merged_date`, `note`.

**남은 한계 (이 시점):** SGIS 경계 폴리곤과의 코드 대조는 여전히 안 됨(→ M2에서 완전히 해결, `reports/m2_admin_units.md` 참고).

**부수 수정 — `Data/` → `data/raw/` 폴더 이동.** 이 프로젝트가 있는 macOS 볼륨은 대소문자를 구분하지 않는 파일시스템(APFS)이라, 기존 최상위 `Data/`(원본 데이터, gitignore 대상)와 README가 계획한 `data/processed/`가 같은 폴더로 취급됐다(`ls -id Data`와 `ls -id data`가 동일 inode). 원본 데이터 두 파일을 `data/raw/`로 옮기고 `.gitignore`의 `Data/` 항목을 제거했다.

## 4부 — 심평원 데이터의 법정동/행정동 불일치 및 매핑 (`data/processed/legal_dong_to_admin.csv`)

작성일: 2026-08-24

2부(M1 구조 제안)는 심평원 병원/약국 데이터의 `읍면동` 컬럼이 "원문 텍스트로 이미 들어있다"고 전제하고, 이를 `adm_code_map.csv`의 행정동 이름과 직접 문자열 매칭하는 1차 조인 전략을 제안했다. 실제로 원본 파일(`data/raw/전국 병의원 및 약국 현황 2026.3/`)을 열어 포항 남구·북구 671건(병의원) + 237건(약국) = 908건을 확인한 결과, **이 전제가 틀렸다: `읍면동` 컬럼은 행정동이 아니라 법정동 단위였다.**

예: 남빈동·대신동·대흥동·덕산동·동빈1가·상원동·신흥동·항구동·학산동은 전부 현재 행정동 기준으로는 **중앙동** 하나에 속한다. `adm_code_map.csv`(29개 현재 행정동)를 그대로 이름 매칭에 쓰면 이런 법정동 이름 908건 중 상당수가 매칭 실패했을 것이다.

**방법:** 포항 남구·북구 레코드만 필터링, `읍면동` 고유값 48개(남구 20 + 북구 28) 추출 → 위키백과 "포항시의 행정 구역" 문서에서 각 행정동이 관할하는 법정동 목록을 조회 → 48개 고유값 전부가 위키백과 관할 목록과 정확히 대응됨을 확인(매칭 실패 0건).

**부수 확인:** `대도동`/`상도동`(→상대동), `해도동` 레코드의 `시군구코드명`이 실제로 `포항남구`로 기록되어 있음을 확인 — 3부에서 발견한 "옛 코드는 북구, 현재는 남구" 구 소속 변경 이슈가 심평원 데이터에는 나타나지 않는다(심평원은 현재 행정구역 기준으로 시군구코드를 매기기 때문). 3부와는 별개의, 새로운 데이터 정합성 이슈였다.

**산출물:** `data/processed/legal_dong_to_admin.csv`(`gu`, `legal_dong_nm`, `admin_dong_nm`). `src/preprocess/admin_join.py`가 이 매핑 + `adm_code_map.csv`(status=current)를 이어 붙여 심평원 레코드에 `adm_cd`를 부여 — 908건 전부 매칭 성공(미매칭 0건).

**남은 한계 (이 시점):** 이름 매칭(1차)만 구현했다 → SGIS 키 확보 후 2차 검증(point-in-polygon) 구현 완료, 결과는 `reports/m2_admin_units.md` 참고(908건 중 11건 불일치, 약 1.2%). 이 매핑은 2026.3 심평원 데이터 스냅샷 기준이며, 데이터가 갱신되면 `admin_join.py`가 미매칭 레코드에 `ValueError`로 즉시 실패하도록 만들어 뒀다.
