이 문서는 README 2절에 정의된 M0 체크리스트 4개 항목을 로컬 원본 파일(`Data/`) 실사 + KOSIS 원격 조회 + 웹서치로 실제 검증한 결과다. 추정이 아니라 직접 연 파일과 API 응답 기준으로 작성했다.

## 결론 요약 — 게이트 상태: **조건부 통과**

핵심 차단 조건이었던 "외국인주민현황이 행정동 단위로 확보되는가"는 **확보 가능(YES)**으로 확인됐다. 다만 그 데이터는 로컬 `Data/`에 이미 있는 게 아니라 KOSIS 원격 조회로 새로 가져와야 한다. 나머지 2개 항목(SGIS 코드 일치, 실태조사 응답형식)은 완전히 닫히지 않았지만, 둘 다 README가 이미 예견한 대안(코드 매핑 테이블, AI 1층 재정의)으로 흡수 가능한 리스크이지 설계 자체를 뒤엎는 문제는 아니다. 따라서 `src/access/` 설계 착수는 가능하되, 항목 2·3은 M1 진행 중 별도로 반드시 닫아야 한다.

## 1. 외국인주민현황 최소 공표 단위 — 시군구 vs 읍면동

**확인 결과: 읍면동(행정동) 단위로 공표됨. 확보 가능.**

KOSIS에 「시군 및 읍면동별 내·외국인 인구현황」(orgId=216, tblId=`DT_216N_B000J2`, 출처: 경상북도주민등록인구통계)이라는 표가 존재하며, 포항시 산하 개별 행정동 단위로 항목이 분리되어 있다. 예를 들어 죽도동(코드 `15216A1100A37010B000J336`)의 외국인 인구는 다음과 같이 조회된다.

| 행정동 | 연도 | 외국인 인구(계) |
|---|---|---|
| 죽도동 | 2023 | 196명 |
| 죽도동 | 2024 | 209명 |
| 죽도동 | 2025 | 221명 |

항목 차원은 총인구/내국인/외국인 3종, 성별(계/남/여) 교차분류까지 지원한다. 포항시 산하 행정동 전체(남구 14개, 북구 22개 — 아래 2번 항목 참고) 각각에 대해 동일한 방식으로 조회 가능하다는 것을 코드 목록 조회로 확인했다.

**주의사항 (KOSIS 조사연혁 경고):** 이 표는 2000년(작성주기 연 1회→반기), 2011년(반기→분기, 연령별 통계 확대) 개편 이력이 있다. 개편 전후 구간을 하나의 연속 시계열로 이어붙여 해석하지 말 것.

**로컬 데이터와의 차이 — 중요:** `Data/경상북도_포항시_연도별인구현황_20260323.numbers`는 이 조건을 만족하지 못한다. 실제로 열어본 결과 이 파일은 **포항시 전체 단위 월별 시계열**(2006-12 ~ 2026-02, 200행)이며, 한국인 남/여·외국인 남/여·세대수 등의 컬럼은 있지만 행정동 구분이 전혀 없다. 즉 지금 로컬에 있는 파일은 M0가 요구하는 해상도가 아니고, 실제로 쓸 데이터는 `src/ingest/kosis.py`가 `DT_216N_B000J2`를 새로 pull하도록 설계해야 한다.

## 2. 포항시 남구·북구 행정동 목록 ↔ SGIS 경계 코드 일치 여부

**확인 결과: 미해결 (⬜). SGIS Open API 키가 없어 경계 파일과의 직접 대조는 이번 세션에서 수행하지 못함.**

다만 KOSIS 자체 행정동 코드 체계는 확보했다. 포항시 산하 행정동 목록(2026-08-14 기준 KOSIS 조회):

- **남구 (14개)**: 송도동, 청림동, 제철동, 효곡동, 대이동, 구룡포읍, 연일읍, 오천읍, 대송면, 동해면, 장기면, 호미곶면, 상대동, 해도동
- **북구 (22개)**: 중앙동, 학산동, 상대1동, 상대2동, 해도1동, 해도2동, 양학동, 죽도1동, 죽도2동, 용흥동, 우창동, 두호동, 장량동, 환여동, 흥해읍, 신광면, 청하면, 송라면, 기계면, 죽장면, 기북면, 죽도동

**중요한 발견 — README 8절이 경고한 리스크가 실측에서 그대로 나타남:** 목록에 `죽도동`과 `죽도1동`/`죽도2동`이 동시에 존재하고, `해도동`(남구 소속)과 `해도1동`/`해도2동`(북구 소속)이 동시에 존재하며, `상대동`(남구 소속)과 `상대1동`/`상대2동`(북구 소속)도 동시에 존재한다. 이는 과거 행정동 통폐합/분동 이력이 KOSIS 코드 체계에 신-구 코드로 남아있다는 뜻이다. SGIS 경계 파일에도 동일한 신-구 혼재가 있을 가능성이 높으므로, `data/processed/adm_code_map.csv` 수작업 매핑이 선택이 아니라 필수 작업이 될 것으로 예상된다. 이 매핑 없이는 죽도동 인구 데이터와 죽도1동/죽도2동 시설 좌표가 서로 다른 폴리곤에 조인될 위험이 있다.

**다음 액션 (M1에서 처리):** SGIS Open API 키 발급 후 포항시 남구·북구 경계 SHP를 받아 위 24개 코드와 대조. 신-구 동 매핑은 통계청 행정구역코드 변경 이력 자료로 확인.

## 3. 다문화가족실태조사 '지원 서비스 요구' 항목 — 응답 형식

**확인 결과: 미확정이지만, 객관식(사전 정의된 서비스 목록에 대한 체크리스트/척도)일 가능성이 높음.**

2021년 전국다문화가족실태조사 보도자료(여성가족부/정책브리핑)는 서비스 이용 경험을 "입국 전 교육 36.2%, 한국사회 적응교육 30.4%" 같은 형태로 보도한다. 사전 정의된 서비스 카테고리별 이용률(%)로 집계·보도된다는 것은 해당 문항이 자유서술형이 아니라 폐쇄형(체크리스트 또는 이용경험 유무 + 향후 필요도 척도) 구조라는 강한 정황 증거다.

**한계:** 원본 조사표(설문지) PDF는 여성가족부 홈페이지에서 JavaScript 트리거 다운로드 방식이라 이번 세션(브라우저 자동화 미사용)에서는 직접 열어보지 못했다. 100% 확정하려면 MDIS(mdis.kostat.go.kr)에서 실제 조사표/코드북 원본을 받아 '지원 서비스 요구' 문항 번호를 직접 확인해야 한다.

**결론 — AI 1층 재정의 필요할 가능성 높음:** 위 정황이 맞다면 README 2절이 명시한 대로 "NLP 토픽모델링" 서술은 성립하지 않는다. 잠정적으로 README가 제시한 대안 — **응답 패턴 기반 잠재클래스 분석(LCA) 또는 다변량 수요 프로파일링**으로 AI 1층을 재정의하는 방향을 권장한다. `src/nlp/demand.py`는 텍스트 토픽모델링이 아니라 체크리스트 응답 벡터 기반 클러스터링으로 설계해야 할 가능성에 대비해야 한다.

## 4. 상가정보·의료기관 데이터의 좌표계와 포항시 레코드 수

**확인 결과: 의료기관 데이터는 검증 완료. 상가정보는 아직 미확보.**

`Data/전국 병의원 및 약국 현황 2026.3/`의 병원정보서비스·약국정보서비스 파일을 직접 열어 확인:

| 파일 | 전국 행 수 | 포항시 레코드 | 좌표 컬럼 | 좌표계(실측) |
|---|---|---|---|---|
| 1.병원정보서비스 | 79,562 | 671건 (북구 397, 남구 274) | `좌표(X)`, `좌표(Y)` | WGS84 십진 경위도 (예: 129.35, 36.02) |
| 2.약국정보서비스 | 25,688 | 237건 | `좌표(X)`, `좌표(Y)` | WGS84 십진 경위도 |

**README 8절의 우려와 다른 점:** README는 "심평원 데이터는 WGS84 도분초 문자열로 오는 경우가 있다"고 경고했지만, 실측 결과 이 두 파일은 이미 십진(decimal degree) 형태의 WGS84(EPSG:4326)다. 도분초 문자열 파싱은 불필요하고, `crs.py`에서는 4326 → 5179 재투영만 하면 된다. (단, 데이터 갱신 시점에 따라 형식이 바뀔 수 있으니 `preprocess/validate.py`에서 좌표 컬럼 타입 검증은 유지할 것.)

또한 두 파일 모두 `읍면동` 컬럼에 행정동명이 원문 그대로 들어있어(예: 죽도동, 흥해읍, 오천읍) `admin_join.py`의 point-in-polygon 매칭 없이도 이름 매칭으로 1차 조인이 가능하다. 다만 2번 항목에서 발견한 신-구 동명 혼재(죽도동 vs 죽도1동/2동) 문제가 여기에도 그대로 적용될 수 있으니 이름 매칭 결과를 좌표 기반 point-in-polygon 결과와 반드시 교차 검증해야 한다.

**미확보:** 상가(상권)정보(소상공인시장진흥공단)는 `Data/`에 아직 없다. 좌표계는 확보 후 별도 검증 필요 (README는 EPSG:5181 계열일 가능성을 언급함 — 실측 전까지는 가정으로만 취급).
