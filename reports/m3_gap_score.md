# M3 — 격차 점수(Gap Score) 프로토타입

작성일: 2026-09-16
근거: README §5 인터페이스 계약(`gap_scores.parquet [adm_cd, fac_type, gap_score, rank, cluster_id]`), §7 방법론 노트, `reports/m2_two_sfca.md`(임계거리 순위 불안정성)

## 공식

`src/gap/score.py`의 `compute_gap_scores()`:

```
gap_score = w_demand × norm(수요) + w_access × (1 − norm(접근성))
```

- **수요(demand)** = `pop_foreign / pop_total` (외국인 인구 **비율**, 절대값이 아님). 절대값을 쓰면 인구 규모가 큰 행정동(오천읍 등)이 외국인 비율과 무관하게 자동으로 수요 상위가 되어, "이 동네에서 외국인 주민이 상대적으로 얼마나 큰 비중인가"라는 격차 진단의 원래 질문과 어긋난다.
- **접근성(access)** = `accessibility.parquet`의 `access_index`(M2, 바닐라 2SFCA, 기본 임계값 3km). `1 − norm(access)`로 뒤집어 "접근성 결핍" 방향으로 맞춘다.
- 두 성분 모두 도메인(`fac_type`)별로 따로 min-max 정규화한다. 현재는 "보건의료" 도메인 하나뿐이라 실질적 영향은 없지만, 향후 "금융" 도메인이 다시 붙었을 때 서로 다른 척도의 `access_index`를 하나로 섞지 않기 위한 설계다.
- `rank`는 `gap_score` 내림차순(1위 = 격차 최대 = 우선순위 최고).

## 가중치 — 0.5/0.5로 확정 (2026-09-22)

`config/weights.yaml`의 `demand_weight`/`access_weight`는 각 0.5다. 처음엔 GM 담당자(최서진)의 정주여건 이론 검토를 거쳐 다른 값으로 바뀔 수 있는 잠정값으로 뒀지만, GM 검수 결과 **중립값(수요·접근성을 동등하게 본다)을 그대로 쓰기로 최종 결정**했다 — 정교한 이론적 도출이라기보다 "굳이 한쪽에 치우칠 근거가 없으니 50/50으로 간다"는 실용적 판단이다. 이 결정 자체를 근거로 기록해 둔다: 상위 4개 동(구룡포읍·호미곶면·장기면·대송면)이 임계거리·가중치 변화에 상관없이 계속 최우선 구간에 남는다는 것(아래 "임계거리 민감도" 절)이 이 결정의 리스크를 낮춰준다 — 가중치를 한쪽으로 크게 기울여도 "어디를 먼저 봐야 하는가"라는 결론 자체는 잘 안 바뀔 가능성이 높다.

`load_weights()`는 두 가중치의 합이 1.0이 아니면 바로 에러를 낸다 — 편집 중 오타가 조용히 결과에 반영되는 것을 막기 위해서다.

## cluster_id는 사분위 구간이지 클러스터링이 아니다

README 인터페이스 계약(`gap_scores.parquet`)에 `cluster_id` 필드가 있고 `src/gap/cluster.py`가 "정책 유형 분류"를 맡을 예정이지만, 이번 M3에서는 별도 클러스터링 모듈을 만들지 않았다. 이유: 현재 특징(feature)이 `gap_score` 하나뿐이다(M4 NLP 수요 신호가 아직 없음). 단변량 특징에 KMeans 등을 돌려도 결과는 정렬 후 구간을 나누는 것과 동일하다 — 라이브러리를 쓰는 것이 "가짜 정교함"이 될 뿐이다. 그래서 `score.py` 안에 `_assign_priority_tier()`로 순위 기반 4분위(1=최우선~4=양호)만 매겼다. **M4가 붙어 결핍 유형(demand_signals.parquet)이라는 두 번째 축이 생기면 다변량 클러스터링으로 교체해야 한다** — 지금 구조는 그 자리를 채우는 임시값이다.

## 임계거리 민감도 — access_index보다 gap_score 상위권이 더 안정적이다

`m2_two_sfca.md`는 "임계거리(1/3/5km)를 뭘 고르냐에 따라 29개 행정동 전부 순위가 최소 한 번은 바뀐다"고 경고했다. `gap_score_sensitivity()`로 같은 검증을 격차 점수까지 이어서 확인했다.

| | 순위가 한 번이라도 바뀐 동 수 (29개 중) |
|---|---|
| access_index만 (m2) | 29 |
| gap_score (수요+접근성 결합) | 25 |

개별 순위 변동은 여전히 크지만(평균 변동폭 4.6), **최우선 구간(top 5)은 임계거리와 거의 무관하게 유지된다**:

| 임계값 | Top 5 (동명) |
|---|---|
| 1km | 구룡포읍·호미곶면·장기면·대송면·청하면 |
| 3km | 구룡포읍·호미곶면·장기면·대송면·청하면 |
| 5km | 구룡포읍·호미곶면·장기면·대송면·**송라면** |

세 임계값 모두에서 top 5에 남는 곳은 **구룡포읍·호미곶면·장기면·대송면 4곳**이다. 원인은 수학적으로 자연스럽다 — 이 네 곳은 인구가 적고 외국인 비율이 상대적으로 높은 남구 외곽 읍·면이면서 의료시설 공급 자체가 희박해, 임계거리를 얼마로 잡든(1~5km) catchment 안에 들어오는 시설 수가 적다는 사실 자체가 잘 바뀌지 않는다. 즉 **수요·접근성을 결합한 gap_score는 access_index 단독보다 "어디가 정말 시급한가"라는 질문에 더 안정적으로 답한다** — 이는 임계거리 민감도 문제(m2_two_sfca.md §7)를 없애는 것이 아니라, 우선순위 판단이 실제로 필요한 상위권에서는 영향이 상대적으로 작다는 것을 보여줄 뿐이다. 하위권 순위(예: 30위권 내 중간 순위)는 여전히 임계거리에 따라 크게 흔들리므로, 특정 동을 "몇 위"라고 단정적으로 인용하는 서술은 피해야 한다(README §7).

## 인터페이스

```
gap_scores.parquet [adm_cd, fac_type, gap_score, rank, cluster_id]
```

- `save_gap_scores()` → `data/processed/gap_scores.parquet`
- `scripts/run_pipeline.py --stage gap`로 실행 가능하도록 연결(이 커밋에서 `access`/`gap` 스테이지를 `NOT_YET_IMPLEMENTED`에서 제거).

## 알려진 한계

- 가중치 0.5/0.5는 GM 검수를 거친 확정값이지만, 이론적으로 정교하게 도출된 값은 아니다 — 위 "가중치" 절 참고.
- `cluster_id`는 실제 클러스터링이 아니라 순위 사분위 — 위 "cluster_id는..." 참고.
- 접근성 성분은 M2 바닐라 2SFCA(기본 임계값 3km) 하나에 고정 — E2SFCA(`reports/m2_e2sfca.md`)나 다른 임계값은 아직 `gap_scores.parquet`(공식 산출물)에 반영하지 않았다.
- 수요 성분(`pop_foreign_ratio`)은 M4 NLP 수요 신호(체감 결핍 유형)를 전혀 반영하지 않은 인구 통계 기반 근사치다 — "실제로 뭐가 부족하다고 느끼는가"는 아직 이 점수에 없다.
