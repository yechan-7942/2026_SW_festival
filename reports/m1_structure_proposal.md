# M1 착수를 위한 구조 제안 (M0 감사 결과 기반)

작성일: 2026-08-14
근거: `reports/m0_data_audit.md`

README 4절의 리포지토리 구조는 이미 확정돼 있으므로 뼈대를 다시 그리지 않는다. 이 문서는 M0에서 실제로 확인한 사실(위 감사 문서)이 그 뼈대 안의 **각 모듈이 어떤 입력을 받고 무엇을 먼저 처리해야 하는지**를 어떻게 바꾸는지 정리한 것이다. 디렉터리·코드는 아직 만들지 않았다 — 구현 전에 팀이 한 번 검토하는 게 나을 내용이라 판단해서 제안 형태로 남긴다.

## 1. `src/ingest/kosis.py` — 우선순위 1순위

가장 먼저 만들어야 할 모듈. `DT_216N_B000J2`(경상북도주민등록인구통계, 시군 및 읍면동별 내·외국인 인구현황)를 pull해서 포항시 남구·북구 행정동 36개 코드(감사 문서 2번 항목 목록) 각각의 총인구/내국인/외국인 시계열을 받아온다. 로컬 `.numbers` 파일은 이 용도로 못 쓴다 — 참고용 시계열(시 전체 장기 추이)로만 남기고 실제 파이프라인 입력에서는 제외.

주의: 조사연혁상 2000년·2011년 개편이 있었으므로, 시계열을 그대로 이어붙이지 말고 이 사실을 `data/MANIFEST.yaml` 주석 또는 함수 docstring에 명시해야 함 (KOSIS 도구 응답이 강제하는 고지 사항).

## 2. `data/processed/adm_code_map.csv` — 예상보다 일찍, 예상보다 중요해짐

원래 README에서는 "행안부·SGIS 코드가 다를 경우"의 대비책으로 언급됐는데, 실제로 열어보니 **KOSIS 코드 체계 자체 안에서도** 신-구 행정동이 동시에 존재한다(죽도동/죽도1동·죽도2동, 해도동/해도1동·해도2동, 상대동/상대1동·상대2동 — 감사 문서 2번 참고). SGIS 경계 파일과 대조하기 전에도 이미 KOSIS ↔ 심평원 데이터 사이에서 이 문제가 터질 수 있다는 뜻. 이 매핑 테이블을 M2보다 먼저, ingest 직후 단계에 세워야 한다. GM 담당자나 컴공 담당자가 국가통계포털 행정구역코드 변경 이력을 보고 수작업 검수해야 하는 항목.

## 3. `src/preprocess/admin_join.py` — 조인 전략 두 단계로

심평원 병원/약국 데이터에는 `읍면동` 컬럼이 원문 텍스트로 이미 들어있다(예: "죽도동", "흥해읍"). 그래서:
1. 1차: 이름 문자열 매칭으로 빠르게 조인 (point-in-polygon 없이도 가능)
2. 2차: 좌표(X,Y) → point-in-polygon으로 교차 검증

1차 결과와 2차 결과가 갈리는 레코드가 있으면 그게 바로 2번 항목의 신-구 동 매핑 문제가 실제로 터지는 지점이다. `validate.py`에 이 불일치를 로깅하는 체크를 넣을 것을 제안.

## 4. `src/preprocess/crs.py` — 예상보다 간단해짐

심평원 병원/약국 데이터는 이미 EPSG:4326 십진 경위도라 도분초 문자열 파싱 로직은 필요 없다. 4326→5179 재투영 한 줄이면 충분. 단, 상가정보(아직 미확보, 소상공인시장진흥공단)는 README가 우려한 대로 EPSG:5181 계열일 가능성이 있으니 그쪽은 여전히 변환 로직이 필요할 수 있다 — 확보 후 재검증 필요.

## 5. `src/nlp/demand.py` — 잠정적으로 토픽모델링 전제를 버림

MDIS 원본 조사표를 아직 못 열어봤지만(다운로드가 JS 트리거라 자동 접근 불가), 여성가족부 보도자료의 서비스별 이용률(%) 보도 방식으로 미루어 볼 때 '지원 서비스 요구' 항목은 사전 정의된 체크리스트/척도형일 가능성이 높다. AI융합 담당자는 텍스트 토픽모델링이 아니라 **응답 벡터 기반 잠재클래스분석(LCA) 또는 다변량 프로파일링**을 1차 설계안으로 잡고 시작하되, MDIS 원본 확인 후 뒤집힐 수 있다는 점을 감안해 인터페이스(`demand_signals.parquet`의 `demand_type`, `intensity` 컬럼 정의)는 README의 계약을 그대로 유지하는 게 안전하다 — 내부 구현 방법만 바뀌고 다음 단계로 넘기는 산출물 스키마는 안 바뀌게.

## 6. `config/pipeline.yaml`의 대상 행정동 목록 — 초안 있음

감사 문서 2번 항목에서 확보한 36개 코드(남구 14 + 북구 22)를 그대로 초안으로 쓸 수 있다. 다만 신-구 동 중복(죽도동 vs 죽도1동/2동 등)을 그대로 넣으면 이중 카운트가 생기므로, 현재 유효한 행정동만 추리는 작업이 이 YAML을 처음 채우기 전에 선행돼야 한다.

## 남은 블로커 (병렬로 처리 가능, 서로 안 막음)

- **SGIS Open API 키 발급** — 컴공 담당. 발급되면 감사 문서 2번 항목 완전히 닫을 수 있음.
- **MDIS 다문화가족실태조사 원본 조사표 확보** — AI융합 또는 GM 담당. 로그인/약관동의가 필요해 보여 브라우저로 직접 받아야 할 가능성이 큼.
- **상가(상권)정보 다운로드** — 컴공 담당. 아직 `Data/`에 없음.

이 세 가지는 서로 의존관계가 없어서 팀원별로 나눠 동시에 처리 가능하다.
