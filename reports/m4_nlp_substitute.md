# M4 — MDIS 원자료 대신 공개 결과보고서로 대체하기로 결정

## 배경

M4(NLP 수요 신호 추출)는 전국다문화가족실태조사 원자료(MDIS)를 입력으로 쓸 계획이었다. MDIS 계정이 뚫려서 실제 신청 절차를 확인해봤다.

## 조사 — MDIS 원격접근서비스(RAS)

이 조사(가구·개인 단위 민감정보 포함)는 **다운로드서비스가 아니라 원격접근서비스(RAS) 대상**이다. 원자료를 로컬 PC로 내려받을 수 없고, 원격분석서버 안에서만 분석 가능하며, 집계 결과표만 국가데이터처 반출승인을 받아야 가져올 수 있다.

신청 절차(8단계): 서약서·이용규정 동의 → 이용신청서(연구계획서 첨부) → 승인심사 → 이용자료 생성 → 비용결제 → RAS 이용(다운로드 불가) → 결과 반출요청 → 반출자료 검토·승인.

**비용**: 기간제 기준 1일 10,000원. 학생(대학원생·휴학생 포함) 70% 할인 적용 시 1일 3,000원. 여기에 승인까지 걸리는 기간이 불확실하고, 연구계획서 승인 여부도 확실치 않다.

## 결정: MDIS 포기, 공개 결과보고서(2차 자료)로 대체

축제 제출 일정과 비용(팀 예산 없음)을 고려해 RAS 신청을 하지 않기로 했다. 대신 여성가족부가 3년 주기로 공개하는 **전국다문화가족실태조사 결과보고서**(집계표, data.go.kr에 공개)를 2차 자료로 쓴다.

이 결정에 따른 근본적인 한계:
- 결과보고서는 **전국/광역시도 단위 집계**이지, 포항 29개 행정동 단위 분해가 아니다. 즉 행정동 간 차등화된 수요 신호를 만들 수 없다.
- 그래서 이 신호는 gap score(M3)처럼 행정동을 구분하는 정량 지표로 쓰기 어렵고, M5 정책 리포트의 LLM 프롬프트에 "포항 전체에 적용 가능한 배경 근거"로 주입하는 용도에 더 맞는다 — `src/nlp/`가 아니라 `src/policy/`에서 고정 컨텍스트로 다루는 구조가 나을 수 있다. 최종 설계는 GM 담당자와 상의 필요.

## 원본 PDF 확보 — 완료 (2026-09-21)

처음엔 웹 조회(`WebFetch`)만으로 원문을 찾으려다 실패했다: `data.go.kr` 메타데이터 페이지는 실제 파일 링크가 없었고, `mogef.go.kr` 게시물(`bbtSn=705039`)은 첨부파일명만 노출하고 다운로드 URL이 JS로 가려져 있었다. 대체로 찾은 `familynet.or.kr`, `kwdi.re.kr` 링크도 각각 무관한 포스터 이미지·학술지였다.

**브라우저 자동화(Claude in Chrome)로 실제 "다운로드" 버튼을 클릭해서 해결했다.** `mogef.go.kr` 정책자료실 게시물(`mp_pcd_s001d.do?mid=plc503&bbtSn=705039`, 제목 "2024년 전국다문화가족실태조사 최종보고서")의 첨부파일 "[용역] 2024년 전국다문화가족실태조사 연구 - 여성가족부(최윤정).pdf"(16,072,074 bytes, sha256 `c7db854985a38ee52f7cdaa5ec5d340afdb7d83beec23b9b99e03b83eb71a645`)를 받아 `data/raw/2024년 전국다문화가족실태조사/`에 두고 `data/MANIFEST.yaml`에 등록했다. 총 914쪽, 한국여성정책연구원이 여가부 연구용역으로 수행.

## 확인된 내용

### 지역 분해는 원천적으로 불가능 — 연구진이 직접 명시

부표 4-2 인근(전체 텍스트 기준 약 37,848행)에 이렇게 적혀 있다:

> "시도별 RSE값은 층화가 세분화되고 지역별 분포도 작아 RSE 값이 안정적이지 않으므로 이에 근거하여 본 연구에서도 시도별 분석은 시도하지 않았다."

즉 **연구진 스스로도 광역시도 단위 분석조차 포기했다** — 표본 설계상 경북 하나만 떼어내도 표준오차가 불안정하다는 뜻. 포항(행정동 단위는커녕 경북 단위로도) 전용 수치를 만드는 건 이 자료로 원천적으로 불가능하다는 게 확정됐다. `경상북도`가 텍스트에 등장하는 곳은 전부 표본설계·가중치 산출용 원표(부록)뿐이고, 분석 결과표에는 등장하지 않는다.

### 그래도 쓸 수 있는 전국 단위 수치 (연구요약, iii~xxii쪽)

M5 정책 리포트 LLM 프롬프트에 "포항 전체에 적용 가능한 배경 근거"로 주입할 만한 것들:

**한국생활 전반의 어려움** (어려움 없음 37.7%, 복수응답 아님 추정)
| 항목 | 비율 |
|---|---|
| 경제적 어려움 | 22.9% |
| 언어 문제 | 20.3% |
| 외로움 | 19.7% |
| 생활방식·관습·음식 등 문화차이 | 19.6% |
| 가족 간 갈등 | 6.0% |
| 친구·이웃 사귀기 | 5.9% |
| 편견과 차별 | 5.5% |
| 공공기관이나 은행 이용 | 3.7% |

**의료 접근성 직결 지표** — README §1의 "의료" 도메인과 바로 연결됨: 지난 1년간 아파서 병원에 가고 싶을 때 가지 못한 경험이 있다는 응답 **4.1%** (2021년 대비 크게 감소).

**자녀 양육 어려움**: 5세 이하는 돌봐줄 사람 찾기 어려움(24.6%) > 배우자·가족과 의견차이(21.6%) > 한국어 직접 가르치기 어려움(17.8%). 6~24세는 교육비 부담(24.9%) > 진학·진로 정보 부족(21.8%) > 학습지도 어려움(19.7%).

**차별 경험**: 13.0%가 경험. 장소별로는 직장(74.6%) > 거리·동네(53.5%) > 자녀 학교·보육시설(34.0%) > 대중교통(30.5%) > 공공기관(27.5%) > 가족·친척(24.0%).

**지원서비스**: 실제 이용률 21.5% vs 요구도(5점 척도)는 취업·창업 지원이 2.58점으로 가장 높음 — 이용률과 요구도 사이 갭이 크다(정책 처방 카드에서 다룰 만한 포인트).

**경제활동**: 고용률 62.7%, 단순노무직+서비스직이 60%, 월평균임금 300만원 미만이 80%.

## 후속 — 경상북도 단위 2차 자료 추가 확보 (2026-09-21)

전국 집계치는 "포항 전용 수치가 아니다"라는 한계가 커서, 사용자 요청으로 더 좁은 범위의 대체재를 검색했다. **경상북도 「외국인주민 및 다문화가족 실태조사」**(경상북도 발주, 이민정책연구원 수행, 2023.11, `mrtc.re.kr`에 공개)를 찾았다 — `data/raw/경상북도_외국인주민_다문화가족_실태조사/`, `data/MANIFEST.yaml`에 등록.

이 조사는 경북을 **5개 권역**으로 나눠 분석했고, **포항시는 "1권역"(포항시·경주시·영천시·경산시·청도군)에 속한다.** 순수 포항 단독은 아니지만 전국 집계치보다 지리적으로 훨씬 가깝다. 여가부 전국 조사에 없는 항목도 있다:
- **보건의료 이용행태**(체류유형별 대처 방식) — "병원에 못 감 4.1%"라는 단일 수치보다 훨씬 구체적: 병원/의원 이용 62.3%, 처방 없이 약국 이용 16.4%, 보건소 10.1%, 본국에서 가져온 약 사용 5.5%, 무료 진료소 2.6%, 그냥 참는다 2.1%.
- **경북 거주 시 어려운 점**(5점 척도): 언어문제(3.25) > 비자/체류자격(3.13) > 경제활동 기회(3.06) ≈ 한국인과 관계맺기(3.06) > 자녀양육·교육(3.05) > ... > 의료기관 이용(2.71) > 주택(2.67) > 음식(2.64).
- **차별 경험률 지역 비교**: 경북 22.4% vs 대구 24.9% vs 전국 20.5%(이 조사가 인용한 전국치 — 여가부 조사의 13.0%와는 조사·문항이 달라 직접 비교 불가, 섞어 쓰지 않음).
- **서비스 수요**: "의료상담 및 진료서비스" 항목이 별도로 있음 — 이용 경험 31.2%, 요구도 5점 척도 4.02점.

`src/policy/context.py`에 `build_context_block()`을 "배경 근거 1(경북, 우선)"과 "배경 근거 2(전국, 보조)"로 분리해서 둘 다 넣었다 — 각 수치가 어느 조사에서 나온 건지 라벨을 명확히 붙여서 LLM이 섞어 쓰지 않게 했다. 받은 파일은 "요약본"(인포그래픽 PDF, 20쪽)만이고, 같은 페이지에 있는 원본 전체보고서는 아직 안 받았다 — 필요하면 추가 확보.

## 설계 방향 (확정)

원래 계획대로 `src/nlp/`가 텍스트를 분류하는 구조는 성립하지 않는다 — 입력이 자유서술 텍스트가 아니라 이미 집계된 고정 수치이기 때문이다. 위 수치들은 **행정동을 구분하지 못하는 전국 배경 지식**이므로, gap score(M3)처럼 행정동별 값을 만드는 게 아니라 **M5 정책 리포트의 LLM 프롬프트에 고정 컨텍스트로 주입**하는 용도가 맞다 — 즉 `src/policy/`에서 다루는 게 구조적으로 깔끔하다. `src/nlp/`는 만들지 않는 방향으로 기운다(README §1의 "NLP" 단계명은 후속 커밋에서 재검토 필요 — GM 담당자와 상의).
