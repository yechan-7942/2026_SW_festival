# M1 — 심평원 데이터의 법정동/행정동 불일치 및 매핑 (`data/processed/legal_dong_to_admin.csv`)

작성일: 2026-08-24
작성자: Claude Code
근거: `reports/m1_structure_proposal.md` 3번 항목 (`src/preprocess/admin_join.py`)

## 배경

M1 구조제안 문서는 심평원 병원/약국 데이터의 `읍면동` 컬럼이 "원문 텍스트로 이미 들어있다"고 전제하고, 이를 `adm_code_map.csv`의 행정동 이름과 직접 문자열 매칭하는 1차 조인 전략을 제안했다. 실제로 원본 파일(`data/raw/전국 병의원 및 약국 현황 2026.3/`)을 열어 포항 남구·북구 671건(병의원) + 237건(약국) = 908건을 확인한 결과, 이 전제가 틀렸다: `읍면동` 컬럼은 **행정동이 아니라 법정동** 단위다.

예: 남빈동·대신동·대흥동·덕산동·동빈1가·상원동·신흥동·항구동·학산동은 전부 현재 행정동 기준으로는 **중앙동** 하나에 속한다. `adm_code_map.csv`(29개 현재 행정동)를 그대로 이름 매칭에 쓰면 이런 법정동 이름 908건 중 상당수가 매칭 실패했을 것이다.

## 방법

1. 원본 두 파일을 로드해 포항 남구·북구(시군구코드명 `포항남구`/`포항북구`) 레코드만 필터링, `읍면동` 고유값 48개(남구 20 + 북구 28) 추출.
2. 위키백과 "포항시의 행정 구역" 문서에서 각 행정동이 관할하는 법정동 목록을 조회 (M1 행정동 코드 매핑 때와 동일한 교차검증 방식).
3. 48개 고유값 전부가 위키백과 관할 목록과 정확히 대응됨을 확인 — 매칭 실패 0건.
4. 부수 확인: `대도동`/`상도동`(→상대동), `해도동` 레코드의 `시군구코드명`이 실제로 `포항남구`로 기록되어 있음을 확인 — `adm_code_map.csv`에서 발견했던 "옛 코드는 북구, 현재는 남구" 구 소속 변경 이슈가 심평원 데이터에는 나타나지 않는다(심평원은 현재 행정구역 기준으로 시군구코드를 매기기 때문). 즉 이번 발견은 M0/M1에서 이미 다룬 신·구 행정동 문제와는 **별개의, 새로운** 데이터 정합성 이슈다.

## 산출물

`data/processed/legal_dong_to_admin.csv` — 컬럼: `gu`(남구/북구), `legal_dong_nm`(법정동), `admin_dong_nm`(현재 행정동). 행정동 자체가 곧 법정동명과 같은 경우(죽도동, 두호동 등)도 항등 매핑으로 포함해 조회 코드를 단순화했다. 위키백과 관할 목록에는 있지만 2026.3 원본 데이터에는 등장하지 않는 법정동(송정동, 괴동동, 장흥동, 덕수동, 동빈2가, 일월동, 여남동)도 향후 데이터 버전 대비용으로 함께 포함했다.

`src/preprocess/admin_join.py` — 이 매핑 + `adm_code_map.csv`(status=current)를 이어 붙여 심평원 레코드에 `adm_cd`를 부여한다. 실행 결과 908건 전부 매칭 성공(미매칭 0건).

## 남은 한계

- 이 조인은 **이름 매칭(1차)만** 구현했다. `m1_structure_proposal.md`가 제안한 2차 검증(좌표 point-in-polygon 대조)은 SGIS 행정동 경계 파일이 없어 아직 불가능 — `admin_join.validate_point_in_polygon()`은 `NotImplementedError` 자리표시자로만 존재한다. SGIS 키 확보 후 반드시 대조해 이름 매칭 결과를 검증해야 한다.
- 이 매핑은 2026.3 심평원 데이터 스냅샷 기준으로 만들었다. 데이터가 갱신되어 새 법정동 이름이 등장하면 `admin_join.py`가 `ValueError`로 즉시 실패하도록 만들어 뒀으니(미매칭 레코드 발생 시), 그때 이 CSV를 갱신하면 된다.
