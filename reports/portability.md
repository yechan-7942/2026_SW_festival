# 다른 도시로의 이식성 점검

작성일: 2026-10-08

"포항용 분석이 아니라 다른 산업도시에 이식 가능한 엔진"이라는 주장(`reports/research_report.md` §6.4)을 실제로 검증하려고 울산 울주군을 대상으로 데이터 확보 가능성을 점검했다. 결론부터 말하면 **코드는 대부분 설정만 바꾸면 되지만, 읍·면·동 단위 외국인 주민 데이터가 도시마다 다른 경로로만 나와서 아직 한 번에 돌릴 수는 없다.** 시범 실행은 하지 않았다 — 핵심 입력이 없는 상태로 돌린 결과를 "이식 성공"으로 보이게 하고 싶지 않았다.

## 도시에 따라 달라지는 부분과 현재 상태

| 입력 | 도시 의존성 | 현황 |
|---|---|---|
| 행정동 경계(SGIS `hadmarea`) | `config/pipeline.yaml`의 `sgis.sigungu_codes`만 바꾸면 됨 | 이식 가능 |
| 집계구 인구 중심점(SGIS `statsarea`) | 위와 동일(`src/ingest/sgis_tract.py`가 `adm_code_map.csv`의 행정동 목록을 따라감) | 이식 가능, 단 `adm_code_map.csv`를 도시별로 만들어야 함 |
| 의료기관(심평원) | 전국 파일이라 `POHANG_SIGUNGU` 필터만 교체 | 이식 가능 |
| 상가정보(소상공인) | 행정동 중심 좌표 반경 검색 — 대상 행정동 목록만 있으면 됨 | 이식 가능(API 호출량 큼) |
| **행정동별 외국인 주민 수** | 포항은 포항시 자체 지역통계(KOSIS 기관 216, `DT_216N_B000J2`, 포항만 수록)를 씀 | **도시마다 다름 — 걸림돌** |
| 법정동→행정동 매핑 | 포항은 `adm_code_map.csv`·`legal_dong_to_admin.csv`를 직접 만듦 | 도시별 수작업 또는 좌표 point-in-polygon으로 대체 필요 |
| LLM 배경 근거 | 경북 전체 집계 수치가 `src/policy/context.py`에 상수로 있음 | 도시별 공개 조사자료 확보 후 교체 필요 |

## 울주군 점검 결과

KOSIS 지자체 통계 검색으로 울주군 읍·면별 외국인 주민 표를 찾았으나 **찾지 못했다.** 나온 것은 울산시 구·군 단위 국적별 외국인, 울주군 읍·면별 총인구·연령별 주민등록인구뿐이다. 외국인 비율이 격차 점수의 수요 축이므로 이 값 없이는 점수를 만들 수 없다.

## 이식하려면 (다음 단계)

1. 대상 시군구의 읍·면·동별 외국인 주민 수를 구한다. 후보: 해당 시·군의 자체 통계 연보, 행안부 지방자치단체 외국인주민현황 읍면동 파일 요청, 지자체 정보공개 청구. 안산·시흥·화성·김포 같은 외국인 밀집 도시는 지자체 통계에 읍면동 표가 있을 가능성이 높다.
2. `config/pipeline.yaml`의 `sgis`, `kosis`, `target_admin_units`와 `POHANG_SIGUNGU`를 대상 도시로 바꾸고, 법정동→행정동 매핑은 좌표 point-in-polygon으로 대체한다.
3. `src/policy/context.py`의 배경 근거를 해당 지역 조사로 교체한다.

위 1번의 데이터만 확보되면 나머지는 설정 교체 수준이다.
